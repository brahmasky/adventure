## 1. Goal

Put the four pre-model context decisions on the registry as rule-only entries that **record and never steer**:

- `context.recall` (A25): which retrieved episodic facts and wiki pages enter the turn's `[context]` block (cosine ≥ gate with an embedding, an FTS hit without one).
- `context.catch_up` (A26): does the planner prompt carry the quick replies Paco got from the lanes since the planner last answered, and how many fit.
- `context.lessons` (A23, the lesson part): which active lessons the spawned child's system prompt holds under the char cap.
- `turn.clarify_cap` (A27, the cap only): Houge has asked its limit of clarifying questions in a row; does this prompt carry the "do not ask another" line.

Each wraps today's code unchanged; the raw answer drives. Proof: the stamped merge-base differential on the R3/R4 supervisor fixture, zero behaviour differences.

## 4. The entries

### 4.0 The recording rule (ADR 0030 §5)
All four decisions are made inside a turn whose run is already claimed, so each row is written at the decision with that run's id and `tool_call_id` null, **and only while that turn is live**: a decision whose turn has ended writes no row (ADR 0030 §5, "a turn that is lost writes no row"; R4 §4.0). The raw code is unchanged either way.
- **The liveness signal is the end itself, not `finished`.** `turn.done("abort" | "end")` resolves `turn.ended` at once (`abortTurn`, `:1571–1573`; `finishLane`), but `finished` is set only in `finishSuccess` / `finishFailure` (`:1595`, `:1611`), after `settle` has awaited `drainJudges` and the todo snapshot (`:862–885`). A consult in that interval would pass a `!finished` guard. `newDeferred` (`:303–306`) therefore also sets `turn.endSignalled = true` inside `done`, synchronously with the resolve, and every R5 guard reads `!turn.endSignalled`. R4's crash guard keeps its `!turn.finished` (changing it would move R4's rows; logged as a follow-up).
- **Recall, catch-up and the cap** are decided in `buildTurnPrompt`'s synchronous stretch after `d.retrieve`. `TurnPromptInput` gains `live?: () => boolean`; the supervisor passes `() => !turn.endSignalled`; absent (one-shot callers, tests) → treated as live. Each consult records only when `live()` is true at the consult. A turn that ended during `retrieve` therefore still writes its `loop_started` row (today's behaviour, unchanged) and **no** R5 row: its prompt never reached a child, so there is no decision to judge.
- **Lessons** are decided at the spawn by the supervisor's own `record()` helper (one recorder per supervisor, the R3/R4 route). The launching turn is passed down, never read from `this.turn`: `ensureSession(fresh, turn)` → `preflightThenSpawn(fresh, turn)` → `spawn(model, turn)` → `preparePaths(turn)`; after `writeSystemPromptFile` (signature unchanged), `if (!turn.endSignalled) this.record(CONTEXT_LESSONS, inputOf(snapshot), turn.req.run_id)` (the threaded type widens to `Pick<Turn, "finished" | "endSignalled" | "req">`). A consult reached after the launching turn ended writes no row; the prompt is still written and the drops still raised (raw behaviour).
No message, fact, page, lesson or lane text is stored (`rowOf` has no input column).

All four: `version: 1`, `stage: "pre_model"`, one `rule` rung, `armed: { rule: "on" }`, `outcomes: []`, **unlocked** (§6.1 carries no L for A23, A25, A26, A27). `input`: `context.recall` `mixed` (Paco's message scored against stored rows); `context.catch_up` `mixed` (it folds Paco's lane messages); `context.lessons` `tool`; `turn.clarify_cap` `tool` (assistant intents only). R12: an `effect` verdict over `mixed` input is allowed for a rule-only entry — `effectProblems` (`registry.ts:100–108`) still requires an effect declared for every verdict but skips the R12 check when the entry has no Jev or model rung; as for `turn.retry`, the amendment states the consequence: adding a Jev or model rung later needs a compliant effect contract, and `entryProblems` fails the suite until it has one.

**One read, one predicate.** Each capture uses the values the raw code already computed, never a second read: the cap's capture comes from the same `getRecentChatTurns` read (§4.4); recall's from the returned `TurnRetrieval`; catch-up's from the one `laneTurnsSince` read; lessons' from the one `renderLessonSection` result.

### 4.1 `context.recall`
- Verdicts `include | none`; `defaultVerdict: "none"`; `fail: "none"` (recorded, never acted on).
- **Consulted** once per `buildTurnPrompt` call **when retrieval was attempted** (`telemetry` present), after `d.retrieve` resolves. Both memory flags off → not consulted (no embed, no read, nothing to judge).
- Input `{ embedding: boolean; facts: number; pages: number; best_admitted: number | null; best_rejected: number | null }`: `facts`/`pages` = the returned arrays' lengths (what `renderContextBlock` renders); `best_*` = the larger of the two sides' telemetry values (null when both null); `embedding` = the facts side's telemetry flag (both sides share one embedding). Rule (first match): `facts + pages > 0` → `include` / `embedded` (embedding) or `fts_only` (no embedding); else `none` / `embed_failed` (no embedding), `dropped_after_gate` (`best_admitted` not null: a candidate on either side passed the cosine gate but none rendered — removed by the core band or by a side's char guard, `episodic-retrieval.ts:126–135`, `wiki-retrieval.ts:106–116`), `below_gate` (`best_rejected` not null: every candidate with a cosine was below the gate), or `unscored` (no candidate had a cosine: none found, FTS-only rows dropped by a guard, or a swallowed read error). Each reason states only what the captured values establish. A test pins `include` ⇔ `renderContextBlock(...) !== ""` on every corpus item. `reasonCodes`: `embedded`, `fts_only`, `embed_failed`, `dropped_after_gate`, `below_gate`, `unscored`.
- Effects: `include` `effect`, reversible true (the next turn retrieves afresh), announced none; `none` `none`.
- Rows: **Decision 1.**

### 4.2 `context.catch_up`
- Verdicts `inject | none`; `defaultVerdict: "none"`; `fail: "none"`.
- **Consulted** on a Telegram planner turn **when there is something to decide**: the read returned at least one lane row, or the read failed. A schedule turn (returns before the read) and a Telegram turn with no lane reply since the planner's last answer are not consults.
- Input `{ read_failed: boolean; available: number; shown: number }` (`available` = rows read, `shown` = `run_ids.length` of `renderCatchUp`'s result). Rule (first match): `read_failed` → `none` / `read_failed` (the read or the render threw); `shown > 0` → `inject` / `all` when `shown === available`, `entry_capped` when `shown === CATCH_UP_MAX_ENTRIES < available` (older exchanges cut by the entry cap), else `trimmed` (cut by the char cap); else `none` / `all_trimmed`. `reasonCodes`: `all`, `entry_capped`, `trimmed`, `all_trimmed`, `read_failed`.
- `catchUp` becomes `{ text, run_ids, available, read_failed }` internally; `renderCatchUp` is unchanged (pure, exported, tested).
- Effects: `inject` `effect`, reversible true, announced none; `none` `none`.
- Rows: **Decision 2.**

### 4.3 `context.lessons`
- Verdicts `full | capped | none`; `defaultVerdict: "full"`; `fail: "full"`.
- **Consulted** once per spawn, in `preparePaths` after `writeSystemPromptFile` (§4.0); never by `systemPromptFingerprint`, the `appliedOf` fallback, the lane, or the other `writeSystemPromptFile` callers (`scripts/live-gate-memory-a1.mjs:100`, tests).
- Input `{ rendered: number; skipped: number; failed: boolean }` from the snapshot (`lessonIds.length`, `skipped.length`, `lessonRenderFailed`). Rule: `failed` → `none` / `render_failed`; `skipped > 0` → `capped` / `char_cap`; else `full`. `reasonCodes`: `char_cap`, `render_failed`.
- Effects: `capped` `tighten`, reversible true (a shorter lesson, a raised cap or a pruned lesson re-renders it at the next spawn), announced none (each drop already raises today's `lesson_dropped` incident, unchanged); `none` `tighten`, reversible true, announced none (`lesson_render_failed` is today's announcement); `full` `none`.
- Rows: `capped` and `none` only (the default writes none). Zero in the DB's history: an outage record.

### 4.4 `turn.clarify_cap`
- Verdicts `allow | cap`; `defaultVerdict: "allow"`; `fail: "allow"`.
- **One predicate, one read.** `turn-context.ts` exports a pure `clarifyCapOf({ trailing, max }): boolean` (`trailing >= max`); `clarifyCapReached` is replaced by `clarifyCapState(d, chatId): { trailing: number; max: number }` (the same read and count), and `buildTurnPrompt` uses `clarifyCapOf(state)` for the notice and the same `state` as the input. The rule's verdict is `clarifyCapOf`'s, so there is no second copy.
- **Consulted** once per `buildTurnPrompt` call.
- Input `{ trailing: number; max: number }`. Rule: `clarifyCapOf` → `cap` / `cap_reached`, else `allow`. `max === 0` caps every turn (a test pins it, raw and rule). `reasonCodes`: `cap_reached`.
- Effects: `cap` `tighten`, reversible true (the next non-clarify reply resets the streak), announced none (the notice is in the planner prompt, never shown to Paco); `allow` `none`.
- Rows: `cap` only.

### 4.5 Recorder seam
`TurnContextDeps` gains `recorder?: DecisionRecorder`; `CoreWorker.ompTurnContext` passes `this.decisionRecorder` (the same recorder the supervisor gets). A private `record(d, i, entry, input)` helper in `turn-context.ts` mirrors the supervisor's (`planner-supervisor.ts:418–421`): absent recorder or `i.live?.() === false` → no `decideSync` call; never throws into the turn. `context.lessons` uses the supervisor's existing helper. Every harness that injects a recorder must pass it to both seams: the `.mjs` fixture (`opts.recorder` → `turnContext.recorder` too) and `tests/helpers/supervisor-harness.ts:207`. A production-wiring test drives `CoreWorker.submitTurn` with a fake session and a seeded clarify streak and requires the `turn.clarify_cap` row, with a scripted retrieval requires the `context.recall` row, and with lessons over a lowered cap requires the `context.lessons` row (R2 lesson: a fixture that injects its own recorder cannot see a constructor that forgets one).

### 4.6 Failure behaviour (R1–R4 carried over)
(a) The insert fails → `decision_record_failed` and one operator alert; (b) a recorder that throws past itself → logged. `decideSync` never throws for a rule-only entry. A rule that throws records its `fail` verdict at the `fail` rung for all four entries (`shouldRecord` records every non-`rule` rung, `decisions/record.ts:29`), while the raw code did what it did: a reader of a `none` / `full` / `allow` row checks `rung` first. For lessons and the cap the `fail` verdict equals the default, so the `fail`-rung row is the only trace; three in an hour page `decision_fallback` (`record.ts:91–104`). The corpus has one planted-throw item per entry expecting exactly that row. Neither fault changes the prompt, the attribution row, the touches, the drops or their order. A recorder fault inside `buildTurnPrompt` or `preparePaths` must not throw into the turn or the spawn (the helper catches).

## 10. Risks
- **Traffic.** `context.recall` is the first R-slice entry on the common path: under 1-A, one row per planner turn with memory on (~112 per 30 days today). Bounded by turns; a row is a handful of columns.
- **A second read sneaking in.** The cap's capture must reuse its one `getRecentChatTurns`; recall's must use the returned arrays, not a re-query; the equivalence tests pin each.
- **The spawn-time run.** The threading must not change spawn order or the joined-start behaviour: a joiner never launches `preflightThenSpawn`, so only the launching turn is passed; the late-launcher item pins no row and asserts the spawn happened.
- **The prompt bytes.** No recording call may run between the pieces of `buildTurnPrompt`'s string in a way that reorders them; the differential compares the full prompt text.

## Decisions needed (Paco, at the spec tap)

**Decision 1 — which `context.recall` consults write a row.**
- **1-A (recommended):** every consult (`alwaysRecord`): `include` and `none`, ~112 rows per 30 days.
