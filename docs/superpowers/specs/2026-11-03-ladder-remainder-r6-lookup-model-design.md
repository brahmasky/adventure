## 4. The entries

### 4.0 The recording rule (ADR 0030 §5, as R5 §4.0)
All three decisions are made inside a turn whose run is claimed: each row carries that run's id and `tool_call_id` null, and is written **only while the turn is live** when it is written.

**When a lane row is written (codex B).** The lane is time-bounded: every later step reads the clock (`beforeReserve`, `lookup-lane.ts:47`) before it starts. A row written synchronously at the decision would put the insert (and, on a fault, the alert) between the decision and the next budget read, so a slow write could turn a search into `lane_timeout` or skip the fetch. The lane entries therefore **decide at the branch and write at the lane's end**: `lookupQuery` and `readStep` push `[entry, input]` onto a per-run list; `runLookupLane` writes the list in order after `lookupSteps` returns or throws (the `lane_threw` path included), only if `!i.signal.aborted` then. No budget read follows that point in the lane. A turn aborted later in the lane (during the compose) writes none of its lookup rows — a lost turn (§5). The corpus pins this with a recorder that advances the fixed clock past the reserve on every call: the searched query, the fetch and the result are unchanged. The lane's existing `tool.wall`/`reader.family` writes stay mid-lane (pre-existing, out of scope §2; logged as a follow-up). `turn.model` writes at the consult, as R5's entries do: after the walk, nothing before the prompt reads a budget clock (the frame-idle timer is armed before the pin and is a timer, not a clock read). The lane entries read `!i.signal.aborted` (§3); `turn.model` reads `!turn.endSignalled` (R5's flag, re-armed per retried leg by `armEnd`). A consult on an ended turn writes no row; the raw code is unchanged either way. No message, query, prompt, URL, digest or model id is stored (`rowOf` has no input column).

All three: `version: 1`, `stage: "pre_model"`, one `rule` rung, `armed: { rule: "on" }`, `outcomes: []`, **unlocked** (§6.1 carries no L for A21, A22). `input`: `lookup.rewrite` `mixed` (Paco's message and recent chat lines go into the Tiny prompt); `lookup.thin` `tool` (the reader's field over search output); `turn.model` `tool` (supervisor state). R12 as in R5: an `effect` verdict over `mixed` input is allowed for a rule-only entry; adding a Jev or model rung later needs a compliant effect contract, and `entryProblems` fails the suite until it has one.

**One read, one predicate.** Each capture uses values the raw code already computed. Where the raw code branches on a predicate, the rule calls the same exported function (§4.1, §4.2); `turn.model`'s rule classifies the walk the code already finished and drives nothing.

### 4.1 `lookup.rewrite`
- **One predicate each, pure refactors in `lane-compose.ts`:**
  - `rewriteFilterOf(message, quoted, ageMs): "no_recent_line" | "long_message" | "needed"` — `ageMs === null || ageMs > REWRITE_RECENT_MS` → `no_recent_line`; else `quoted || [...message.trim()].length <= REWRITE_MAX_CHARS` (code points, as today) → `needed`; else `long_message`. `needsRewrite(...)` becomes `rewriteFilterOf(...) === "needed"`.
  - `queryCheckOf(raw, message): { kind: "same" } | { kind: "invalid" } | { kind: "query"; q: string }` — the strip as today; `/^same[.!。]?$/i` → `same`; empty, newline, `q.length > QUERY_MAX_CHARS` (UTF-16 units, as today) or a URL → `invalid`; else `query`. `validateQuery(raw, message)` becomes `kind === "query" ? q : message`. (The empty-string check runs before the `SAME` test today and both return the bare message; the classifier calls an empty answer `invalid`.)
  Both wrappers return byte-identical results for every input; each keeps today's comparison orientation (`ageMs > REWRITE_RECENT_MS`, so a `NaN` or negative age stays `needed`-eligible exactly as today). Unit tests pin the equivalence over the existing cases plus the boundaries: 40/41 code points, a 40-code-point message of astral characters (80 UTF-16 units), 30 min ± 1 ms, `NaN` and negative age, 120/121 UTF-16 units, `same.`, `SAME!`, `same。`, empty, a URL, a newline.
- **Consulted** once per lookup run that enters `lookupQuery`, on **every** return path (filter false `:54`, `bound <= 0` `:56`, the call `:58`): `lookupQuery` captures the step at each branch and pushes one consult before a single `return` (written at the lane's end, §4.0). `no_fast_leg` (before the query step) is not a consult.
- Input `{ step: RewriteStep }`, `RewriteStep = "no_recent_line" | "long_message" | "no_time" | "late" | "failed" | "same" | "invalid" | "rewritten"`, set where `lookupQuery` branches: the filter's answer; `bound <= 0`; `r === LATE`; `r === null` (the call threw) or `!r.ok`; else `queryCheckOf(r.answer, userText).kind` (`query` → `rewritten`). A `LATE` or failed call still passes `"SAME"` to `validateQuery` exactly as today.
- Rule: `rewritten` → `rewrite` / `rewritten`; else `bare` / the step. `reasonCodes`: `rewritten`, `no_recent_line`, `long_message`, `no_time`, `late`, `failed`, `same`, `invalid`. Which reasons are code and which the model: `no_recent_line`, `long_message`, `no_time` (code before the call); `late`, `failed` (the call's outage); `same`, `rewritten` (the model's answer); `invalid` (code over the model's answer).
- Verdicts `rewrite | bare`; `defaultVerdict: "bare"`; `fail: "bare"`.
- Effects: `rewrite` `effect`, reversible true (the next lookup asks afresh), announced none (the query is not shown; the source line shows what was read), what "the validated rewrite is the search query and the reader's objective"; `bare` `none`.
- Rows: **Decision 2.**

### 4.3 `turn.model`
- **Consulted** once per completed pin walk on a live turn: in `pinFirst` (`leg: "first"`) and in `promptRetry` (`leg: "retry"`), as **the first statement after `if (r === ENDED) return …`** — before `noLeg`, `failTurn`, `turn.pinFailed = true`, the `planner_model_reset_failed` incident and the `throw r.error` (`:746–750`, `:978–983`). `failTurn` calls `done`, which sets `endSignalled`; a consult placed after it would guard its own `none` row away. Row order on the run: the `turn.model` row, then the incident. An `ENDED` walk is not a consult; `promptTop` with no session (`failTurn` before any pin) is not a consult. Never at `candidates()`, `turnChain`, `spawnChain` or `currentCandidate` (each runs several times a turn).
- Input `{ leg: "first" | "retry"; outcome: "ok" | "pin_failed" | "exhausted"; stepped: boolean; refused: number }`, captured around the walk from values the supervisor already holds: `stepped` = `turn.role` after the walk differs from before it; `refused` = the pins omp refused **in this walk**: `iterations = legsTriedAfter − legsTriedBefore` (each walk iteration increments `turn.legsTried` exactly once, `:762`; the counter persists across retry legs, so only the difference is walk-local), and `refused = iterations − 1` for `ok`/`pin_failed`, `iterations` for `exhausted`. R4's `legsTried` semantics are not changed. A test drives a retry leg after an earlier leg's refusal and requires `next_leg`, not `refused`.
- **`head` is the first eligible candidate** (codex W): `turn.chain` is the role's candidates minus what this child already refused (`turnChain`, `:482`), and that set lasts until a fresh spawn (`:1020`). So a later turn on the same child can pin the role's second model with no refusal in its own walk: that is `head`. The refusal itself was recorded once, as `fallback/refused`, on the turn that hit it. A corpus item drives the two turns.
- Rule (first match): `exhausted` → `none` / `no_leg`; `pin_failed` → first leg `held` / `pin_failed` (the turn answers on the model the child holds), retry leg `none` / `pin_failed` (the retry fails the turn); `stepped` → `fallback` / `stepped_up`; `refused > 0` → `fallback` / `refused`; `leg === "retry"` → `fallback` / `next_leg`; else `head`. `reasonCodes`: `stepped_up`, `refused`, `next_leg`, `pin_failed`, `no_leg`. No model id or role is a reason code.
- Verdicts `head | fallback | held | none`; `defaultVerdict: "head"`; `fail: "head"`.
- Effects: `head` `none`; `fallback` `effect`, reversible true (the next turn starts from its first eligible candidate again; a refusal lasts for the child's life), announced none, what "a later leg of the role, or the next role up, answers; a step-up is ledgered `routed_escalation` as today"; `held` `effect`, reversible true, announced none, what "the turn answers on the model the child already holds; `planner_model_reset_failed` as today"; `none` `none`, reversible true, announced none, what "the turn fails `no_planner_leg` or `retry_failed` with today's text and incident" (nothing is tightened; the failure is today's).
- Rows: **Decision 1.**

## Decisions needed (Paco, at the spec tap)

**Decision 1 — which `turn.model` consults write a row.**
- **1-A (recommended):** only when the pin left the role's head (`fallback`, `held`, `none`), the default `head` writes none. To date that would have been **zero** rows: no pin has ever been refused or stepped up, and no retry leg has run since R4 shipped (the five compose errors predate it). A `head` row would add one row per planner turn (~112 per 30 days) saying what `turn.gear` (the role) and the turn's `llm_attempt` rows (the model) already hold.
- **1-B:** every consult (`alwaysRecord`), one row per planner turn and per retry leg. An outcome could then attach to "this turn ran on its head", which nothing judges today.

**Decision 2 — which lookup consults write a row.**
- **2-A (recommended):** every consult of both lookup entries (`alwaysRecord`). The lane ran once in its life, so the cost is nil, and both errors become judgeable once an outcome signal exists: a rewrite that searched the wrong thing (`rewrite`) and a bare search that needed the chat's context (`bare/no_recent_line`, `long_message`, `late`); a read judged answered that was not (`none/answered`).
- **2-B:** non-default only (`rewrite`, `fetch`). A missed rewrite and a skipped fetch leave no row.
