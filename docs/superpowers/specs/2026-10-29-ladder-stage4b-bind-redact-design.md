## 4. The entries (pattern: `entries/tool-path.ts` v2, `entries/fetch-ssrf.ts`)

```ts
// src/decisions/entries/approval-bind.ts
export type ApprovalBindVerdict = "bound" | "unbound";
export const APPROVAL_BIND: Entry<{ ok: boolean; code?: string }, ApprovalBindVerdict> = {
  id: "approval.bind", version: 1, stage: "pre_tool", input: "tool", locked: true,
  question: "Does this consume bind the approved row to this exact action, owner and requester?",
  verdicts: ["bound", "unbound"],
  ladder: [{ kind: "rule", name: "consumeBinding", decide: rule }],   // ok → bound; else unbound + the sink's code if listed
  fail: "unbound", defaultVerdict: "bound", alwaysRecord: true, outcomes: [], armed: { rule: "on" },
  effects: { bound: { kind: "none", reversible: true, announced: "none" }, unbound: { kind: "tighten", reversible: true, announced: "none" } },
  reasonCodes: ["no_sink", "unknown_approval", "not_approved", "expired", "action_mismatch", "owner_mismatch", "requester_mismatch", "lease_lost"],
};
```
Reason codes: the omp sink's seven codes verbatim, plus `no_sink` for P3; any other code → no `reason` (the row carries `null`, `record.ts:64`). The run-level sink's eight codes are **not** listed: that path records through a no-op recorder (§5), so they could never be written (senior S1); a unit test on the rule pins that an unlisted code yields a row with `reason_code` null. `alwaysRecord`: every omp-sink consume is a Paco tap being spent (43 in 26 days), and the row is the decision id §4.3 wants as ladder-move evidence.

```ts
// src/decisions/entries/secret-redact.ts
export type SecretRedactVerdict = "clean" | "masked";
export const SECRET_REDACT: Entry<{ masked: boolean; seam: RedactSeam }, SecretRedactVerdict> = {
  id: "secret.redact", version: 1, stage: "settle", input: "tool", locked: true,
  question: "Did this outbound report carry a known secret value (ADR 0015) that was masked before it was cut?",
  verdicts: ["clean", "masked"],
  ladder: [{ kind: "rule", name: "brokerValues", decide: rule }],    // masked → { verdict: "masked", reason: seam }; else clean
  fail: "masked", defaultVerdict: "clean", outcomes: [], armed: { rule: "on" },
  effects: { clean: { kind: "none", reversible: true, announced: "none" }, masked: { kind: "tighten", reversible: true, announced: "none" } },
  reasonCodes: ["final_report", "failure_report", "evolution_report"],
};
```
`masked` is `redact(text) !== text`, computed on the input before `trim()`/cut. `fail: masked` labels a thrown rule as the cautious answer; nothing branches on it (R1). **A row means a masking attempt, not a queued report:** no row for a clean text; one row per wrapper call whose text carried a known value — including a call whose enqueue then returns `duplicate` or `conflict` or throws on insert (the decision is taken while the payload is built, before `enqueueNotification`'s dedup, `:7386–7459`). A row never holds text (ids, enums, the seam code). Coverage is the three report wrappers only; the cards (R3) and the ledger (R2) are not counted, and the digest/ADR wording says so (senior W4).

Both entries: `entryProblems` empty; `locked` and in `LOCKED_ENTRY_IDS`; one rule rung; no `system_one`/`model`/`paco` rung (a registry test pins that the two ids have exactly one rung, of kind `rule`).

## 5. The single call sites (move, don't improve)

**`approval.bind` — `CapabilityRunner.execute`, P3+P4 (`capability-runner.ts:192–219`).** Extract the block into one private `bindApproval(input, …): { ok: true } | { ok: false; result: CapabilityResult; code: string }` that returns **exactly** today's two failure results (P3's `error_ref` string; P4's `"${code}: ${message}"`) and calls the sink **once** with the same argument object (same field set and order, same random ids, the `standing_trial` spread unchanged). Right after it returns, before any branch ("returns" = the sink returned; the adapter has not run yet, so a consume that succeeds and an adapter that then fails is `bound`): `decideSync(APPROVAL_BIND, { ok, code }, { run_id: input.run_id ?? null, tool_call_id: input.tool_call_id ?? null, recorder })` with the same `recorder` the runner already built (`:120`). Then the raw result drives the branch as today (R1). Rules:
- Reached only when `approved_approval_id` is set (so a first call that asks writes no bind row; a standing use writes none — Decision 1).
- `denied_on_revalidation` (P2) returns before the block: no bind row (the consume was never attempted); `tool.policy` keeps that row.
- A sink that **throws** propagates exactly as today, with no bind row (a throw is not a verdict; R2).
- **Coverage is narrowed, by name:** the run-level path (eval fixture only, `eval-runner.ts:256`; 0 live rows) records through the runner's no-op recorder (`core-worker.ts:801–809` passes none), as tool.policy does there today; the differential **requires zero** `approval.bind` rows on that path (codex B4).
- `execute` is already ~125 lines (`capability-runner.ts:98–222`); this slice does not grow it, and the new `bindApproval` helper is under 50 lines. Splitting `execute` is not a precondition (senior W2).

**`secret.redact` — one private `RunStore.redactReport(seam, run_id, text): string`** that replaces the three `truncateForChat(…, this.redact)` calls at `:7275`, `:7306`, `:7327`: it computes `out = this.redact(text)`, and **only when `this.redactionEnabled`** calls `decideSync(SECRET_REDACT, { masked: out !== text, seam }, { run_id, tool_call_id: null, recorder: this.decisionRecorder })`, then returns `truncateForChat(text, this.redact)` — the same function, the same arguments, so the stored bytes, `payload_hash` and the chat-turn copy are unchanged by construction (the redactor runs twice on a report; it is a pure closure, `secret-broker.ts:72–76`). With the firewall off: no decision, no row (as today, nothing is masked). The recorder:
- is injected, not imported: `RunStore.open/openInMemory` options gain `decisionRecorder?: (store: RunStore) => DecisionRecorder`, built in the constructor after `migrate()`. Reason: `record.ts` imports `run/incident-alert.js` → `invariant-sweep.js` → `run-store.js` at run time; a store import of `record.ts` would be a cycle [read of the four import lists]. Absent → a no-op recorder;
- **the options are built in one importable place** (senior B1): today `storeOptions` is a module-local const in the top-level script `cli.ts:34`, which no test or gate can import, so a forgotten line would ship a store with `redact` but no recorder while every gate stays green. A new `src/run/store-options.ts` exports `storeOptionsFor(broker?: SecretBroker)`, used by `cli.ts` **and** by the live gate and the rollback check; a unit test pins that with a broker the result carries both `redact` and `decisionRecorder`, and without one still `decisionRecorder`. The option type makes `redact` require `decisionRecorder` (`{ redact; decisionRecorder } | { decisionRecorder? }`), so `{ redact }` alone does not compile;
- writes on the store's connection at the moment the payload is built. `enqueueNotification` opens no transaction (`:7386`) and its callers do not wrap it (`core-worker.ts:2321, 2348, 2652, 2672, 3608, 4174, 4223, 4228`), so the row is not tied to the outbox insert: a duplicate re-enqueue adds a second row, and an insert failure leaves a row with no outbox row (semantics above, senior W1, codex W1). Where a caller does hold an outer transaction that rolls back, the row rolls back with it — tested, not assumed;
- cannot recurse: R1 is reached only through the three report wrappers; the recorder's failure path (`recordFailed` → `openAlertedIncident` → `openIncident` → ledger R2, and `alertOpened` → unredacted `enqueueNotification`) never reaches R1 [traced]. A test pins it (a recorder that fails every write: the report is enqueued with the masked text, exactly one `decision_record_failed` incident, the call returns).

## 6. The differential (Stage 4's gate column: "command corpus, path corpus and policy matrix identical", plus binding and redaction)

**Harness:** `scripts/check-ladder-stage4-differential.mjs --old-dist <dir> [--base <sha>]` loads the corpora, runs each item through the old build and through this build (each against its own temp DB, VACUUM copies where a DB is read), and compares projections. Old builds come from worktrees verified by `scripts/old-dist-provenance.mjs`. **Bases:** command and path corpora against **`548cb87`** (the last commit before Stage 3 registration; `command-matcher.ts` unchanged since `55d3ac6` 2026-10-01 and `gate-path.ts` since `86f4601` 2026-10-20 [git log]) — this proves Stage 3's wiring of `tool.shell_class` and `tool.path` too, which its smoke gate never compared; policy, binding and redaction against **`1451a66`** (pre-4B; Stage 4A intentionally changed policy v3 and the tap binding), plus the policy matrix's no-`standing` half against `548cb87` as well. Vitest characterisation tables, written red-first in the plan's first task, pin the same items inside the suite.

**What the cross-build comparison can and cannot show (senior S3).** `classifyCommand`, `gateTargets` and `decideCapability` are pure and untouched by 4B (`command-matcher.ts` last changed `55d3ac6`, `gate-path.ts` `86f4601`, both before `548cb87`), so comparing them across builds is tautological and is kept only as a cheap control. The weight is on the **bridge-seam projection**: the card's label, whether the call asked, the gate's deny code, and the `tool.path` / `tool.shell_class` / `tool.policy` rows. The planted-divergence self-test proves the comparator works, not that the corpus covers anything; coverage is pinned separately below.

**Coverage pins (codex S1).** Each corpus has a required minimum item count and a named branch list; the harness FAILs (not passes on an empty set) when an extraction comes back short or a named branch has no item: command ≥ 100 test-table literals + **147** distinct transcript commands + the 7 ADR 0028 misses, and at least one item each of `external_write`, `destructive`, `plain` and `unseen shell script`; path — every `gateTargets` branch listed in item 2 plus **13** transcript inputs; policy — every `CapabilityDecision.reason` string in `tool-policy.ts` `REASON_MAP` reached at least once; binding — every row of item 4; redaction — every case class of item 5 with its own count.
