# 11 — Harness ingredients: external analysis and Houge mapping

*2026-10-04. omp facts from `omp --help` (18.4.4) and `~/.bun/install/global/node_modules/@oh-my-pi/pi-coding-agent/src` (read-only). Houge facts from `AGENTS.md`, ADR 0028, `docs/ROADMAP.md`, `src/omp/planner-session.ts`.*

## 0. The one-sentence answer

The research → proposal → decision → spec → build → verify lifecycle is almost entirely a **harness** property. The same model scores differently in different harnesses (Terminal-Bench 2: Opus 4.7 68.9 % in Claude Code vs 66.1 % in Terminus 2; GPT-5.5 83.1 % in Codex vs 78.0 % — [Snorkel](https://snorkel.ai/leaderboard/terminal-bench-2-1/), [llm-stats](https://llm-stats.com/benchmarks/terminal-bench-2)). Weng: the harness "orchestrates execution and decides how the model thinks and plans, calls tools and acts, perceives and manages context, stores artifacts, and evaluates results" ([Weng 2026-07-04](https://lilianweng.github.io/posts/2026-07-04-harness/)). omp *ships* most ingredients; Houge starts the planner with `--tools read,edit,write` and switches them off by choice, and three remaining gaps are invariants, not omissions.

## 2. Evidence on autonomy length

- **Horizon.** METR TH 1.1: Opus 4.5 50 % horizon 320 min [170, 729], GPT-5 214 min; doubling 196.5 days overall, 88.6 days since 2024; the suite "has relatively few tasks that the latest generation of models cannot perform" ([METR](https://metr.org/blog/2026-1-29-time-horizon-1-1/)); 2026 points sit at 14–20 h and saturate it ([Apiar](https://apiardata.com/statistics/ai-autonomous-task-horizon/)). The **80 % horizon is 4–6× shorter** ([METR paper](https://arxiv.org/html/2503.14499v3)) — the number that matters for an unattended daemon.
- **Harness delta at fixed model.** Terminal-Bench 2: +2.8 for Opus 4.7 in Claude Code, +5.1 for GPT-5.5 in Codex, over Terminus 2. SWE-bench Verified: Opus 4 73.2 % in SWE-agent vs 76.8 % in mini-SWE-agent — a harness can *hurt* when its primitives fight the model ([mini-swe-agent](https://github.com/swe-agent/mini-swe-agent), [HAL](https://arxiv.org/pdf/2510.11977)). The gap is small on short tasks and grows with length, because the harness owns state and verification.
- **Where long runs break.** Planning errors, memory limitation and catastrophic forgetting "account for a substantial portion of failed trajectories"; 72.5 % of failures are process-level, 27.5 % design-level ([Long-Horizon Task Mirage](https://arxiv.org/html/2604.11978v1)). The signature is **one early error that cascades**: after the first mistake agents recover in 30.5 % of runs and never detect it in 38.5 % ([2609.17930](https://arxiv.org/html/2609.17930)); early exits are 19 % of unresolved runs, "the agent stops on its own despite not yet satisfying the hidden verifier" ([2607.08964](https://arxiv.org/html/2607.08964)). METR: premature abandonment is o1's dominant failure (16/32). Weng: "the model declares success despite noisy or failed experiments".
- **Implication.** Cheapest counters: (a) an oracle the model cannot satisfy by assertion (tests, reviewer, live gate); (b) a plan artifact re-read at every phase boundary.

## 3. Human-in-the-loop: how products wait hours or days

- **Codex cloud**: "Each task has its own workspace and can keep working while your computer is asleep"; review is its own phase: "Inspect changed files and check results, request follow-up changes, and commit or open a pull request when you're ready" ([docs](https://learn.chatgpt.com/docs/cloud)). Decision surface = **diff + test output**; the PR records the decision.
- **Devin**: "Devin will respond in-thread to your session"; `sleep`/`mute`/`archive` park a session indefinitely, any thread message wakes it; output is a PR ([Devin Slack](https://docs.devin.ai/integrations/slack)).
- **Claude Code**: plan mode is the gate (plan file, approve before edits); `AskUserQuestion` offers typed options; `--continue`/`--resume` let a task "span multiple sittings"; scheduled runs "can't ask clarifying questions" ([common workflows](https://code.claude.com/docs/en/common-workflows)). Generic guidance: "pause for human feedback at checkpoints or when encountering blockers" ([Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)).
- **Open Telegram agents**: persist the paused state as `PENDING_APPROVAL`, one message with inline **Approve / Deny**, resume on callback ([agent-space #26](https://github.com/dhakad22klx/agent-space/issues/26), [zeroclaw #1865](https://github.com/zeroclaw-labs/zeroclaw/issues/1865)).

**Minimum decision surface for a Telegram-first agent** (derived): (1) a *decision card*: one question, 2–4 labelled inline buttons plus free text, recommendation marked; (2) a *linked artifact*: the spec/plan file (Telegram's 4096-char cap means a `sendDocument` attachment or a stable path; Houge already caps cards at 3000 chars); (3) a *diff card*: files changed, test line, review verdict, Merge/Reject (Houge's [Merge & reload] is this); (4) a *durable wait*: the goal record, not the chat turn, holds the pending question, so the planner serves other turns and the answer resumes the goal days later; (5) a parked wait is silent until woken (Devin's `sleep`).

## 4. Self-improving agents: what is actually deployed

- **Eval-gated self-modification** is the only variant with repeatable gains: DGM 20.0 → 50.0 % on its SWE-bench subset, 14.2 → 30.7 % Polyglot, validated by benchmark runs under "sandboxing, human oversight" ([DGM](https://arxiv.org/abs/2505.22954)). Weng's limits: "the base model must be capable enough to improve the mechanism"; "many research claims do not have a fast and precise verifier, and the same is true for many real-world tasks"; a judge-model signal "may learn reward hacking tricks"; STOP improved with GPT-4 but *degraded* with GPT-3.5/Mixtral ([Weng](https://lilianweng.github.io/posts/2026-07-04-harness/)). Field incident: an agent faked a test log, then trusted it ([DEV](https://dev.to/p0rt/the-agent-faked-a-test-log-then-believed-it-self-editing-harnesses-have-a-provenance-problem-3id6)).
- **Voyager-style skill libraries** work "in constrained environments with deterministic execution verification"; open-ended self-generated skills average **−1.3 pp**, 1 of 5 configurations improved ([SoK](https://arxiv.org/html/2602.20867v1)); unbounded libraries drift ([Library Drift](https://arxiv.org/html/2605.19576)); 202 skills cut pass rate 21 % ([2605.24050](https://arxiv.org/html/2605.24050v1)).
- **Reflexion-style lessons**: positive in benchmarks; no controlled production gain published; same accumulation risk as skills.
- **Agent writes its own tools**: shipped in coding harnesses (omp has `manage_skill`, `learn`, `autoresearch`, an "experimental" `autolearn`), no failure-rate data outside benchmarks.

**Verdict:** the only evidenced recipe outside benchmarks is *small bounded proposals + hard external verifier + human merge* — exactly Houge's self-write pipeline and the A1 lesson design (caps 240/120, cosine gate 0.42, evidence check). Houge is ahead on lifecycle control, behind on *what the loop can propose* (§5, row 5).

## 5. Mapping to Houge

omp 18.4.4 built-ins (`tools/builtin-names.ts`): `read bash edit ast_grep ast_edit ask debug ida eval github glob grep find lsp checkpoint rewind context_notes new_context security_scan task wait todo web_search write memory_edit retain recall reflect learn manage_skill`. Houge passes `--tools read,edit,write` (`src/omp/planner-session.ts:15`); "native, disabled" below means one flag plus a policy-hook allowlist entry — *if* the invariants permit.

**Hardware.** Fan-out and compaction are network-bound; the 2018 CPU is not the limit (local LLM judges stay out). Two vitest runs at once would contend with the daemon; serialise.

**By construction, Houge lacks three things:** (1) a *goal* object that outlives a Telegram turn and holds plan, pending decision and phase; (2) a planner-reachable, test-runnable workspace for its own code (write-denied by hard line a); (3) subagent fan-out under the policy hook (disabled by `--tools`, and unprobed against the one-extension rule). Everything else is present, native, or a flag.
